# Jenix FieldForce — Backend First

You are working on a production-grade employee field-management system.

## Technology

* Backend: Node.js + TypeScript
* Database: MongoDB + Mongoose
* Future frontend: React + TypeScript + Capacitor
* Future Android native functionality: small reusable Kotlin Capacitor plugins
* Existing native video-call plugin already exists — DO NOT recreate it.
* Every source file MUST remain under 200 lines.
* Prefer small focused modules over large files.
* Do not over-engineer.
* Do not redesign unrelated existing code.

## IMPORTANT EXECUTION RULE

Your current objective is **BACKEND ONLY**.

Do NOT start:

* React UI
* frontend design
* Kotlin implementation
* Capacitor plugin implementation
* WebRTC/video plugin
* Android native code

You may define backend API contracts needed by those future components.

Complete the backend before moving to any frontend work.

SUPER_ADMIN
? COMPANY_ADMIN

# 5. Location Ingestion

Future Kotlin Capacitor plugin will send location batches.

Design backend for batch ingestion.

Example payload:

```json
{
  "deviceId": "abc123",
  "points": [
    {
      "timestamp": "ISO_DATE",
      "latitude": 26.9,
      "longitude": 75.8,
      "accuracy": 12,
      "speed": 4.2,
      "heading": 120,
      "battery": 72,
      "mockLocation": false
    }
  ]
}
```

Requirements:

* authenticate device/user
* validate coordinates
* validate timestamps
* reject absurd/future timestamps
* support offline batch upload
* prevent accidental duplicates
* efficient MongoDB bulk insert
* index by companyId + employeeId + timestamp

Location records must NOT be embedded inside employee documents.

Use a separate collection suitable for high-volume history.

Provide APIs for:

* batch ingest
* employee latest location
* employee route between start/end timestamps
* company latest employee locations

Do not calculate complex route analytics yet.
